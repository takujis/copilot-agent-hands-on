この Skill は、ユーザーの問い合わせ内容を確認し、明示的な承認を取得したうえで、Dataverse MCP Server を使用してサポートチケットを作成します。

## ルール

- 問い合わせ内容は、ユーザーが明示的に伝えた事実のみを使用して作成する
- エージェントによる推測、補完、想像を問い合わせ内容に含めない
- エージェントが提案した対処方法を、ユーザーが実施したものとして記載しない
- ユーザーが実施したと明示していない内容を、実施済みと推測しない
- ユーザーが問い合わせ内容を明示的に承認した場合のみ、サポートチケットを作成する
- Details は、ユーザーが承認した問い合わせ内容をそのまま使用する
- Details の内容を要約し、10～50文字程度の分かりやすい Title を生成する
- Details を分析して Category を決定する

## Category

Category は以下から1つ選択する。

- `PasswordReset`
- `AccessRequest`
- `EmailIssue`
- `TeamsIssue`
- `DeviceIssue`
- `NetworkIssue`
- `ApplicationIssue`
- `SecurityIssue`
- `Other`

Category が判断できない場合は、`Other` を使用する。

## 使用するツール

この Skill では Dataverse MCP Server の以下のツールのみを使用する。

- describe
- read_query
- create_record

## チケット作成時の確認

### ユーザーが最初からチケット作成を希望した場合

ユーザーに問い合わせ内容を確認し、以下のように確認する。

> お問い合わせ内容は、以下でよろしいですか？
>
> {問い合わせ内容}

ユーザーが問い合わせ内容を明示的に承認した場合のみ、サポートチケットを作成する。

### 会話の途中でチケット作成に進む場合

これまでの会話でユーザーが明示した事実のみを要約し、以下のように確認する。

> ここまでのお話をもとにしますと、お問い合わせ内容は、以下でよろしいですか？
>
> {問い合わせ内容}

ユーザーが修正した場合は、修正版の問い合わせ内容で再確認する。

ユーザーが問い合わせ内容を明示的に承認した場合のみ、サポートチケットを作成する。

## 実行手順

1. Support Ticket テーブルのスキーマを確認する
2. ユーザーが承認した問い合わせ内容を Details とする
3. Details から Title を生成する
4. Details から Category を決定する
5. サポートチケットを作成する

| 値 | 設定内容 |
|------|------|
| Title | Details の内容を要約して生成したタイトル |
| Details | ユーザーが承認した問い合わせ内容 |
| Category | Details を分析して決定したカテゴリ |

6. 作成したレコードの Ticket Number を取得する

7. 作成したサポートチケットをユーザーに案内する

案内には少なくとも以下の情報を含めること

- Ticket Number
- Title
- Details
