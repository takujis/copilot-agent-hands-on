# 5. エージェントフローにプロンプトツールを追加する

ここまでで、エージェントを通してサポートチケットの発行まで実施できましたが、システム部門側として、これらのサポートチケットを適切なエンジニア、あるいは部署にエスカレーションするにあたり、サポートチケットの内容をある程度カテゴライズする必要があります。ここでは一つの解として、ツールとしてプロンプトを使い、お問い合わせ内容からカテゴライズします。

## 5.1. [プロンプトを実行する] アクションを追加する

1. Copilot Studio の左ナビゲーションから [フロー] をクリックして、[Create a ticket] フローをクリックして開きます。
2. フロー デザイナーの画面で、フローの [エージェントがフローを呼び出したとき] トリガーと [新しい行を追加する] アクションの間の [+] をクリックして、[プロンプトを実行する] を選択して追加します。
3. 追加した [プロンプトを実行する] アクションの設定で、[プロンプト] のプルダウンをクリックし、[+ 新しいカスタム プロンプト] をクリックします。

## 5.2. プロンプトを作成する

プロンプトビルダーの画面の [指示] に、以下のテキストを入力してください。

> **画面の見え方**
> プロンプトビルダーは左右 2 ペイン構成です。左側が [指示] の入力エリア、右側が [モデル応答] のプレビューエリアです。指示の入力エリアの下部には、変数を挿入するための [+ コンテンツを追加する] ボタンがあります。

```text
下記のサポートチケットは、社員からのITサポートへの問い合わせ内容です。この内容をもとに、最も適切なカテゴリを1つ選んでください。カテゴリは以下の中から選択してください。カテゴリは大分類と小分類がありますが、小分類を答えてください。
回答形式は、必ず以下のようにしてください:
例: 2.5 VPN接続エラー

1. PC・ハードウェア関連
1.1 電源・起動不良
1.2 画面表示・モニターの問題
1.3 キーボード・マウスの不具合
1.4 バッテリー・電源アダプターの問題
1.5 本体の異音・発熱

2. ネットワーク・インターネット関連
2.1 Wi-Fi接続不良
2.2 有線LANの問題
2.3 社内ネットワークへの接続不可
2.4 インターネット接続不可
2.5 VPN接続エラー

3. メール・アプリケーション関連
3.1 Outlookの不具合（起動・送受信）
3.2 Teamsの接続・通知問題
3.3 Office製品（Word/Excel等）の動作不良
3.4 業務アプリケーションのエラー
3.5 ライセンス・認証の問題

4. セキュリティ・認証関連
4.1 パスワード忘れ・リセット
4.2 アカウントロック・ログイン不可
4.3 多要素認証（MFA）のトラブル
4.4 権限・アクセス制御の問題
4.5 セキュリティ警告・ウイルス検出

5. 周辺機器関連
5.1 プリンターの接続・印刷不良
5.2 スキャナーの認識・動作不良
5.3 外部ディスプレイ・プロジェクターの問題
5.4 USB機器の認識不良
5.5 Webカメラ・マイクの不具合

6. ソフトウェアインストール・設定
6.1 新規インストール依頼
6.2 バージョンアップ・更新の相談
6.3 設定変更・初期化の依頼
6.4 インストールエラーの対応
6.5 社内標準ソフトの導入

7. その他・不明
7.1 問い合わせ内容が複数カテゴリにまたがる
7.2 内容が曖昧で分類できない
7.3 その他の技術的な相談

[サポートチケット]
詳細:
```

## 5.3. 入力用の変数を追加する

入力したプロンプトの最下部の "詳細" 文字列の右側に、入力用の変数を追加します。

1. "詳細" の右にカーソルを置いて、[+ コンテンツを追加する] から [テキスト] をクリックします。
2. この変数の名前とサンプルデータに以下を記述し、[閉じる] をクリックします。

   | 項目 | 値 |
   | --- | --- |
   | 名前 | 問い合わせ内容 |
   | サンプル データ | モニタがブラックアウトして表示されない |

   > **画面の見え方**
   > 追加した変数は、指示の文中で色付きのトークン (タグ) として表示されます。

## 5.4. プロンプトの名前と出力形式を設定する

1. 既定で設定されている `カスタムプロンプト 2026/・・・・` というプロンプトの名前を `チケットのカテゴライズ` に変更します。
2. [モデル応答] の右側にある出力形式の選択で、[JSON] を選択します。

## 5.5. プロンプトをテストして保存する

1. 左側の [指示] セクションの右上の [テスト] をクリックします。
2. 結果が [モデル応答] に表示され、内容に問題がないことを確認し、[保存] をクリックします。

   > **補足**
   > 出力形式を JSON にしているため、モデル応答には `category` などのキーを持つ JSON が表示されます。この `category` を次の手順で Dataverse の列にマッピングします。

## 5.6. プロンプトの入力と Dataverse への反映を設定する

1. プロンプトの変数 [問い合わせ内容] には、このフローの入力である [Details] を設定します。
2. プロンプトを実行してお問い合わせの内容からカテゴリが推論されるので、その結果を Dataverse にも反映させます。フローの既存の [新しい行を追加する] アクションを選択して、[詳細パラメーター] の右の [すべて表示] をクリックします。
3. 詳細パラメーターの中から、サポートチケットテーブルの [カテゴリ] 列を探します。カテゴリに、動的コンテンツとして、[プロンプトを実行する] アクションの出力である [category] を選択します。
4. [カテゴリ] 列に `category` のトークンが設定されたことを確認します。
5. フローを [下書きを保存する] をクリックして保存し、[公開] をクリックして公開します。

## 5.7. フロー単体でテストする

> **Note**
> 本来であれば、ここで、エージェントフロー単体のテストをしておくことをお勧めします。以下は今回のシナリオでこの時点でテストを行う手順です。

1. 右上の [テスト] をクリックして、[手動] を選択して [テスト] をクリックし、テストを実施します。
2. テストでフローを実行するために、このフローの入力パラメーター (Name / Email / Details) を設定し、[フローの実行] をクリックします。

   > **Note**
   > 実際にメールが送信されますので、メール送信してもよい送信先を入力してください。

3. フローの実行結果を確認し、Dataverse のサポートチケットテーブル内に、新規のサポートチケットとして、カテゴリ列も含めてレコードが作成されていることを確認してください。

## 5.8. エージェントをテストする

1. エージェントのテストから、次のプロンプトを入力します。

   ```text
   アプリのライセンスはどのようにして申請すればいいですか
   ```

2. 該当する情報が見つからず、この質問に対してユーザーが求める回答が返されない動作が想定されます。サポートチケットの作成を案内されたら、`はい` や `サポートチケットを発行してください` を意味する内容を入力するなどして、サポートチケットを作成します。
3. メールが自動送信されたか、および Dataverse のサポートチケットテーブルにレコードが作成されたかを確認してください。
4. [エージェントをテストする] ペインの右上のリセットアイコンをクリックし、会話をクリアします。
5. 次のプロンプトを入力します。

   ```text
   サポートチケット SR-1003 の状況をおしえてください。
   ```

   > **Note**
   > SRID (上の例では `SR-1003`) は、サポートチケット発行時にエージェントから返された ID を使用してください。
