# Agent Builder でエージェントを作成する

この手順では、RFP（提案依頼書）を分析し、案件概要、必須要件、評価基準、提案リスク、確認事項、推奨アクションを整理する RFP Analysis Agent を作成します。

## RFP Analysis Agent を作成する
1. [Microsoft 365 Copilot](https://m365.cloud.microsoft/) にアクセスします。
2. 職場または学校アカウントでサインインします。
3. 左側のナビゲーションの [エージェント] で、[新しいエージェント] を選択します。
4. Agent Builder が表示されたら、右上の [スキップ→] を選択します。  
5. [名前] (Defaultでは「新しいエージェント」) に以下を入力します。  
   ```text
   RFP Analysis Agent
   ```
6. エージェント名のすぐ下 [説明] に以下を入力します。  
   ```text
   RFP、仕様書、審査基準などを分析し、案件概要、必須要件、評価基準、リスク、確認事項、推奨アクションを整理するエージェントです。
   ```

### ナレッジを追加する
7. [ナレッジ] で、ファイルをアップロードするためのボタンを選択します。
8. [**Proposal Review Guide.pdf**](../assets/Proposal%20Review%20Guide.pdf) ファイルをアップロードします。
9. アップロードしたファイルが [アップロード済みファイル] に表示されることを確認します。  
   Proposal Review Guide は、顧客課題、価値、要件、評価基準、セキュリティ、導入、運用、調達条件など、RFPをレビューするための共通基準として使用します。  
   分析対象となる RFP は案件ごとに異なるため、ナレッジとして登録せず、テスト時にチャットへ添付します。
> [!NOTE]
>
> Proposal Review Guide は、顧客課題、価値、要件、評価基準、セキュリティ、導入、運用、調達条件など、提案をレビューするための共通基準として使用します。
分析対象となる RFP は案件ごとに異なるため、ナレッジとして登録せず、テスト時にチャットへ添付します。

### Web 検索を有効にする
10. [ナレッジ] で、[すべての Web サイトを検索します] をオンにします。
11. [指定したソースのみを使用する] はオフのままにします。  

> [!NOTE]
>
> Web 検索は、提案候補となる製品やサービスの補足調査に使用します。RFP に記載された要件、期限、金額、評価基準などの正式条件は、Web の情報ではなく RFP を優先します

### インストラクションを設定する
12. [指示] または [Instructions] に以下を入力します。
```text
# Role

あなたは企業および官公庁の RFP（提案依頼書）を分析し、提案チームの案件理解と提案準備を支援する RFP Analysis Specialist です。

利用者から RFP、仕様書、審査基準、質問回答書などが提供された場合は、Proposal Review Guide を参照しながら分析してください。

# Analysis Principles

- RFP、仕様書、審査基準、質問回答書などの正式文書を最優先の情報源として扱うこと。
- Proposal Review Guide の観点を参考に分析すること。
- 添付された文書に記載されていない内容は推測しないこと。
- 不明な内容は「未記載」または「要確認」と明記すること。
- 重要な結論には根拠となる資料名を示すこと。
- 複数の情報源で内容に差異がある場合は、その差異を明示すること。
- 法務、契約、公共調達、個人情報保護、情報セキュリティに関する最終判断は行わず、「専門家への確認が必要」と明記すること。

# Product Recommendation

利用者から提案候補となる製品やサービスについて質問された場合は、以下を実施してください。

- RFP の要件と顧客課題に対応する製品またはサービスを整理する。
- 公開 Web の情報を利用する場合は、可能な限り公式情報を優先する。
- 製品ごとに対応する要件、期待できる効果、考慮事項を整理する。
- 一般提供（GA）、プレビュー、将来提供予定の情報を区別する。
- 製品仕様、ライセンス、価格、提供地域については最新の公式情報で再確認が必要であることを明記する。
- RFP への適合を断定しない。

# Output Format

RFP の分析を依頼された場合は、以下の構成で回答すること。

## Executive Summary
案件の概要を 3～5 行で要約する。

## 顧客の目的と課題
顧客が解決したい課題と期待する成果を整理する。

## 必須要件
必須要件を箇条書きで整理する。

## 評価ポイント
評価項目、配点、選定上の重点を整理する。

## 提案上のリスク
導入、運用、スケジュール、体制、セキュリティなどの主要リスクを整理する。

## 確認事項
RFP 上で不明な内容や顧客へ確認すべき事項を整理する。

## 顧客への質問案
提案前に確認すべき質問を優先度付きで整理する。

## 推奨アクション
提案チームが次に実施すべきアクションを整理する。

# Information Labels

回答では必要に応じて以下のラベルを使用すること。

- [事実] 正式文書に記載されている内容
- [Web] 公開 Web から取得した補足情報
- [推奨] 提案上の推奨事項
- [未確認] 資料から判断できない内容
- [矛盾] 複数の情報源で内容が一致しない事項
- [要専門確認] 法務、契約、調達、個人情報保護、情報セキュリティ等の確認が必要な事項
```

### プロンプトの候補を設定する
13. [推奨プロンプト] を確認します。
14. 以下のプロンプトの候補を追加します。
    
| タイトル | メッセージ |
|----------|------------|
| 3分理解 | この RFP を提案責任者が 3 分で理解できるように要約してください。 | 
| リスクと確認事項 | Proposal Review Guide の観点に従って、この案件の主要リスクと顧客への確認項目を整理してください。 | 
| 要件整理 | この RFP の要件に対応する Microsoft の製品やサービスの候補を、最新の公式 Web 情報を確認して整理してください。 |

### エージェントを作成する
15. 設定内容を確認し、右上 [作成] をクリックします。
16. ポップアップメッセージでエージェントが正常に作成されたことを確認し、[エージェントに移動する] をクリックしてCopilot Chat に移動してください。


## エージェントをテストする
### テスト 1: RFP の概要を確認する（推定所要時間：20秒）
1. 新しいチャットを開始します。
2. チャット入力欄に以下のいずれかの RFP ファイルを添付します。
   - [**企業版_生成AI・AIエージェント活用基盤_RFP_サンプル.pdf**](../assets/企業版_生成AI・AIエージェント活用基盤_RFP_サンプル.pdf)
   - [**官公庁版_行政事務生成AI活用環境整備_RFP_サンプル.pdf**](../assets/官公庁版_行政事務生成AI活用環境整備_RFP_サンプル.pdf)
3. チャット入力欄に以下のメッセージを入力して送信します。  
   ```text
   この RFP を提案責任者が 3 分で理解できるように要約してください。
   ```
4. エージェントの回答内容を確認します。<br>期待される動作:
   - 案件の背景、目的、対象範囲が整理されること
   - 重要な期限、予算、評価基準が整理されること
   - RFP に記載されていない情報が推測で補完されていないこと
   - 重要な内容に根拠となる文書が示されること

### テスト 2: Proposal Review Guide （今回使用する提案レビュー基準書）を利用した分析を確認する（推定所要時間：3分）
1. 新しいチャットを開始します。
2. テスト 1 で使用した RFP ファイルを添付します。
3. チャット入力欄に以下のメッセージを入力して送信します。  
   ```text
   この案件の主要リスクと顧客への確認質問を整理して、Excelを作成してください。
   ```
5. エージェントの回答内容を確認します。<br>期待される動作:
   - 提案失格、要件漏れ、実現性、セキュリティ、AI 品質、スケジュール、体制、費用などの観点でリスクが整理されること
   - 質問に、確認理由と優先度が含まれること
   - 法務、契約、調達、セキュリティに関する内容に、専門家への確認が必要である旨が示されること

### テスト 3: Web 検索を利用した提案候補を確認する（推定所要時間：30秒）
1. 新しいチャットを開始します。
2. テスト 1 で使用した RFP ファイルを添付します。
3. チャット入力欄に以下のメッセージを入力して送信します。  
   ```text
   この RFP の要件に対応する Microsoft の製品やサービスの候補を、最新の公式 Web 情報を確認して整理してください。
   ```
5. エージェントの回答内容を確認します。<br>期待される動作:
   - RFP の要件と製品またはサービスの候補が対応付けられること
   - Web から取得した内容が [Web] として区別されること
   - 可能な限り公式情報が示されること
   - 提供状況、ライセンス、価格などは再確認が必要である旨が示されること  
   Web の検索結果は実行時点によって変わるため、参加者ごとに回答内容が異なる場合があります。

## エージェントを共有する

作成したエージェントを他のユーザーが利用できるようにする場合は、エージェントを共有します。
1. Microsoft 365 Copilot の左側のナビゲーションで RFP Analysis Agent を確認します。
2. RFP Analysis Agent の [...] を選択し、[エージェントを共有] を選択します。
3. 共有範囲を選択し、[適用] をクリックして設定を保存します。
4. 表示された共有リンクをコピーし、利用者へ共有します。  
> [!NOTE]
> 共有されたエージェントは、利用者がアクセスできる情報のみを使用します。実際の RFP や社内資料をチャットへ添付する場合は、ファイルの機密区分と組織の情報取扱いルールを確認してください。
   
## オプション: 顧客ヒアリングメモを添付する

この手順は発展演習です。基本演習が完了した後、RFP と顧客ヒアリングメモを同じチャットに添付し、正式条件と顧客の背景情報の差分を分析します。

### RFP と顧客ヒアリングメモを添付する（推定所要時間：30秒）
1. 新しいチャットを開始します。
2. 使用する RFPファイル と、対応する顧客ヒアリングメモを添付します。
   - 企業版 RFPファイル を使用する場合は、[**企業版_顧客ヒアリングメモ.docx**](../assets/企業版_顧客ヒアリングメモ.docx) を使用します。
   - 官公庁版 RFPファイル を使用する場合は、[**官公庁版_顧客ヒアリングメモ.docx**](../assets/官公庁版_顧客ヒアリングメモ.docx) を使用します。
3. チャット入力欄に以下のメッセージを入力して送信します。  
   ```text
   RFP と顧客ヒアリングメモを比較し、正式条件、追加要望、矛盾、未確認事項を整理してください。
   ```
5. エージェントの回答内容を確認します。<br>期待される動作:
   - RFP の内容が正式条件として扱われること
   - ヒアリングメモの内容が [ヒアリング] として区別されること
   - 文書間の数値や条件の違いが [矛盾] として整理されること
   - 正式に確認すべき事項が質問案として整理されること  
   官公庁案件では、非公式なヒアリング情報を正式条件として使用せず、公告後の正式文書と質問回答を優先してください。

## 学習内容の確認

このハンズオンでは、以下の内容を学習しました。
- Agent Builder で業務に特化したエージェントを作成する方法
- 分析対象となる RFP をチャットへ添付する方法
- 共通ナレッジをエージェントに追加する方法
- 公開 Web の情報を補足調査に使用する方法
- インストラクションで情報源の優先順位と回答ルールを指定する方法
- 作成したエージェントをテストする方法
- （オプション）複数文書の差分を分析する方法  

>[!IMPORTANT]
>実際の業務では、エージェントの出力をそのまま採用せず、参考情報として活用し、RFP の原文、公式情報、顧客の正式回答を確認してください。
> 
>法務、契約、公共調達、個人情報保護、情報セキュリティに関する事項については、エージェントの回答を最終判断とせず、必ず担当部門または専門家に確認してください。。
